# IDA Pro MCP Technical Reference

This document captures current runtime architecture and behavioral contracts for the host server.

## Runtime architecture

`ida-pro-mcp` is split into:

1. **Host MCP server** (`ida_mcp_stdio.py`)
   - Speaks MCP JSON-RPC over stdio.
   - Owns session metadata, runtime process lifecycle, tool aliasing, response shaping, and docs/wiki indexing.
2. **IDA runtime bridge** (`src/ida_pro_mcp/server_script.py`)
   - Runs inside IDA Python.
   - Dispatches tool calls to modules under `src/ida_pro_mcp/ida_mcp/tools/`.
3. **Tool modules**
   - Implement analysis/edit/debug operations by action.
   - Host advertises tool contracts via `tools/list`.

## Session model

- Sessions are persisted under runtime cache state (`IDA_MCP_CACHE_DIR` or OS default state dir).
- Session metadata includes `session_id`, `binary_path`, generated `idb_path`, options, tags, notes, and access timestamps.
- **Current contract:** `session(action="create")` requires `binary_path` and does not accept `idb_path`/`use_existing`.
- Existing sessions are reused by matching `binary_path` unless `force_new=true`.
- Non-session tools can omit `idb`; host resolves to active session context automatically.

## Tool schema and metadata contract

- Source of truth:
  - `TOOLS`
  - `TOOL_ACTIONS`
  - `TOOL_ARG_SCHEMAS`
  - `build_input_schema()`
- `tools/list` is served by host and includes per-tool:
  - `name`
  - full `description`
  - full `inputSchema`
- Default mode is **full** so schemas/descriptions are directly available to the LLM at load time.

### tools/list modes

- `full`: complete descriptions and full schema (default).
- `lean`: reduced descriptions and compact schema typing.
- `ultra`: minimal description + tiny invocation schema.

Mode is controlled by `IDA_MCP_TOOLS_LIST_MODE` and may be overridden by `IDA_MCP_MONOLITHIC_TOOL_DESCRIPTIONS=1` forcing `full`.

## Response shaping pipeline

All tool responses pass through host response controls:

- `_response_mode`, `_compact`, `_qol_mode`
- field projection/omission (`_response_fields`, `_response_omit`)
- size controls (`_response_max_items`, `_response_max_string`, `_response_char_budget`)
- table/batch compacting and truncation continuation
- error detail shaping (`_error_details`)

Wrapper actions (`grep`, `pick`, `head`, `tail`, `next`, `stats`) are injected at schema level for action-based tools.

## Wiki subsystem

- Wiki root defaults to `docs/wiki` (or `IDA_MCP_WIKI_DIR` override).
- `wiki` tool indexes topics and supports list/read/search/semantic_search/sections/index.
- If static docs are missing, the host can provide generated fallback docs for tools.

## Installer defaults (current)

Installer writes MCP env defaults aimed at direct LLM usability:

- `IDA_MCP_MONOLITHIC_TOOL_DESCRIPTIONS=1`
- `IDA_MCP_TOOLS_LIST_MODE=full`
- `IDA_MCP_RESPONSE_MODE=compact`
- `IDA_MCP_QOL_MODE=balanced`
- additional compact/truncation budgets for response safety

## Documentation generation

- `docs/TOOLS_REFERENCE.md` is generated from live schema metadata.
- `docs/wiki/tools/*.md` is generated from live tool metadata/schemas.
- `docs/wiki/INDEX.md` is generated from wiki tree content.
- `.agents/tool-docs/*.md` are generated by `scripts/generate_tool_skills.py`.

When tool actions/args are changed, regenerate these docs to keep published contracts accurate.
